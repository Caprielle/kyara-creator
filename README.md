# kyara-creator：授業用キャラクター設定作成スキル（Gemini向け）

教科書を使った授業で、学習者の対話相手となる人物（キャラクター）の設定をすばやく作成・編集するためのスキルです。授業のねらいに合わせて人物の立場や考え方を整理し、GeminiのGemで使える対話用プロンプトを生成します。

## 開発の背景

「インターフェース論」の受講学生による企画グループの一員として、以下のワークショップの準備に取り組んでいます。本スキルは、その準備に用いる人物設定の作成支援ツールとして開発しています。

| 項目 | 内容 |
|---|---|
| 研究会 | 学習科学青山研究所2027年度研究会：生成AIと教育の現在地（仮） |
| プログラム | 第３部：生成AIと教科書活用 |
| 対象ワークショップ | 生成AI×教科書で学ぶワークショップ |
| 企画 | 「インターフェース論」受講学生 |

## 目的

教科書の内容や学習目標に沿った人物設定を短時間で作成し、授業準備の負担を減らすことを目指します。

作成する人物には、それぞれの立場、経験、大切にしていることなどを設定します。学習者がAIの演じる人物と対話し、異なる立場から教科書の内容を考え、自分の考えを見直す活動に活用します。

## スキルでできること

| 操作 | 内容 |
|---|---|
| 新規作成 | 必要設定と確認済みの必須設定を自動で再利用し、今回の役割に関する指定を反映した独立・完全なプロンプトを生成します。未確認の必須項目は先に確認し、未指定の任意設定は制約内で自動生成します。 |
| 追加・編集 | 明確に依頼された場合だけ、既存の設定やプロンプトを変更・追加・統合します。 |
| 出力 | 保存・編集用の「設定資料」と、Gemの指示欄に貼り付ける「Gem用プロンプト」を生成します。 |

提供された資料の事実と、対話のために創作した人物設定を区別します。教科書の内容が必要な場合は該当箇所を提供し、不明な内容を事実として補わないようにします。

人物設定は、以下の「役割カード」の形式で整理します。複数の役割を一つの設定にまとめることもできます。

## ファイルと出力

| 名前 | 用途 |
|---|---|
| [`kyara-creator.md`](kyara-creator.md) | Geminiに読み込ませる、人物設定の作成・編集用スキルです。 |
| [`README.md`](README.md) | 開発の背景と使い方をまとめた説明書です。スキルへの読み込みは不要です。 |
| 設定資料 | スキルが生成する、保存・編集用の人物設定です。 |
| Gem用プロンプト | スキルが生成する、人物として対話するための指示です。 |

## Geminiへの設定

1. アップロード用に `kyara-creator.md` のコピーを作り、ファイル名を `SKILL.md` にします。
2. Geminiウェブ版の「カスタマイズ」→「スキル」を開きます。
3. アップロードから `SKILL.md` を選び、内容を確認して「作成」を押します。
4. チャットで `/`（画面によっては `@`）を入力し、`kyara-creator` を選びます。

スキルの利用には、18歳以上のログイン済みアカウントと「アクティビティの保存」が必要です。有料のGoogle AIサブスクリプションは不要です。手順・利用条件は[Google公式ヘルプ](https://support.google.com/gemini/answer/17094296?co=GENIE.Platform%3DDesktop&hl=ja)を参照してください。

## 基本の使い方

1. **教材や授業の条件を渡す。** 手書きの人物設定、既存のカードやプロンプトも使えます。
2. **必須4項目を確認する。** 「学習内容・知識点・学習目標・共通状況」の候補が表で示されます。一つずつ質問に答え、全項目を確認します。資料に書いてある内容も、読み取りが正しいか確認します。
3. **人物の基本案を見る。** 全4項目の確認後、各役割に必要設定が適用され、未指定の任意設定が制約内で自動生成されます。任意項目を一つずつ埋める必要はありません。
4. **完成版を依頼する。** 「設定資料とGem用プロンプトを出力してください」と伝えます。すでに完成版を依頼していれば、必須4項目の確認後に出力されます。確認前に完成版を出すことはありません。
5. **保存して使う。** 「設定資料」は再編集用に保存し、「Gem用プロンプト」の本文全体をGemの指示欄に貼り付けて保存します。操作は[Gemの公式ヘルプ](https://support.google.com/gemini/answer/15146780?hl=ja)を参照してください。

### 依頼の例

~~~text
学習内容は「市場のはたらきと独占禁止法」です。
知識点は「効率、公正、市場」です。
学習目標は、安い価格が異なる立場に与える影響を比較し、
独占禁止法の意義を自分の言葉で説明できることです。
共通状況は、授業上の仮定として、近所のスーパーが
もやし1袋を1円で売ろうとしていることです。
1円は店頭販売価格で、卸値や原価は与えていません。
もやし業者、主婦、八百屋、スーパーの店長を使ってください。
必須4項目を一つずつ確認し、ほかの人物設定は制約内で自動生成してください。
~~~

この価格と登場人物は依頼例の設定です。重量や原価などが判断に必要になった場合は、共通状況として確認し、AIが数値を補いません。別の話題にもやしの条件を持ち込むことはありません。

## 設定の三分類

分類は「誰が内容を決めるか」で分けます。共通の設定か役割別の設定かは、保存する場所の違いです。

| 分類 | 内容の決め方 |
|---|---|
| 必要設定 | スキル内にある各役割の既定ルールです。すべての役割に自動適用し、利用者には入力・確認を求めません。 |
| 必須設定 | 利用者に一つずつ質問し、全4項目の明確な確認を得ます。未確認のまま完成版を生成したり、AIが代わりに決めたりしません。 |
| 任意設定 | 利用者の指定を優先し、未指定部分を制約内で自動生成します。項目ごとの入力や採用許可は不要です。 |

### 必要設定：各役割の既定ルール

| 項目 | 自動適用する内容 |
|---|---|
| 対話相手 | 中学生に合う表現や例を使います。 |
| 役割としての応答 | 設定された人物の立場と事情から答えます。 |
| 視点の数 | 各役割の1ターンの回答で提示する視点は一つまでです。 |
| 学びの引き出し方 | 本時の知識点や答えを直接説明せず、具体的な事情から考えを引き出します。 |
| 最後の問いかけ | 各役割の回答の最後に、考えるための問いを一つだけ置きます。 |
| 話題の軌道修正 | 連続4ターン離題したら、第4ターンの回答で元の話題に戻します。学習者の発言が話題に戻ったら回数をゼロにします。 |
| 判断の出発点 | 人物自身の利益、責任、生活や仕事の事情を優先します。 |

1ターンは学習者の1回の発言と、それに対する回答です。全員モードで複数の役割が答えても離題を重複して数えず、切り替えなどの管理操作は数えません。この7項目は人物としての対話の規則です。人物カードの作成中は、必須設定の確認として一度に一つだけ質問します。

### 必須設定：利用者が確認する4項目

| 項目 | 確認する内容 |
|---|---|
| 学習内容 | 授業の主題、単元、教材の対象範囲。 |
| 知識点 | 理解してほしい概念と関係。提供された既習・未習の範囲も保持します。 |
| 学習目標 | 対話後に何を理解・比較・説明・判断できるようにしたいか。 |
| 共通状況 | 出来事、問い、条件、数値、役割別の指定条件、授業上の仮定、資料・根拠。 |

確認状態は「未確認・要補足・確認済み」です。すでに明確に確認した項目は聞き直さず、複数の役割で共有します。「任せる」「未設定でよい」だけでは必須項目を確認済みにしません。

### 任意設定：制約付き自動生成

| 項目 | 内容 |
|---|---|
| 目的・優先順位 | 達成したいこと、避けたいこと、初期の見方と理由、考えを変える条件。 |
| 性格・生活背景 | 性格、価値観、家族構成、生活事情。 |
| 具体的な経験・行動 | 経験、日常の工夫、行動、予定、行動する意欲。 |
| 人物の認識・心配 | 人物が知っていること、本人の見方、望み、心配、知らないこと。 |
| 対話の手がかり | 確認済みの知識点や目標に結び付く具体例、比較、問い返し、観察点。 |
| 話し方 | 人物らしい口調、言葉遣い、説明の仕方。必要設定は変更しません。 |

未指定の目的・優先順位は、日本語圏でその役割に一般的に想定される責任や関心から生成します。たとえば主婦なら家計・費用対効果・栄養、店長なら利益・集客・経営の継続です。

生成内容は確認済みの授業条件と既存設定に合わせ、「自動生成した役割設定（創作）」と示します。原価、利益、取引量、法的判断、教科書の引用などは創作で埋めません。判断に必要な条件が足りなければ、共通状況の確認に戻ります。人物の心配を必然の結果にしたり、正解や全員の合意を先に決めたりしません。

## 設定資料と既存カードの取り込み

設定資料には、必要設定、確認済みの必須設定、役割ごとの任意設定を記します。設定名・版番号・役割ID（`R01`など）・所属話題は管理情報として保持します。

「役割・他者との関係」という独立項目は使いません。役割名はカードのタイトルに残し、元の取引関係や背景は共通状況・人物背景へ移します。役割名や関係を新たな必須質問に増やしません。

既存カードの家族構成、生活事情、望み、心配、行動、因果関係、引用、リンクは分類変更後も保持します。提供された条件、本人の認識、自動生成した創作、不明な事実を区別します。「任意」は既存情報を削除してよいという意味ではありません。

## 完成したGemでの対話

最初は全員が回答するモードです。各役割は通常、最後の問いを含めて2〜3文で答え、全員モードでも各役割に必要設定の7項目を適用します。

| 入力例 | 動作 |
|---|---|
| `もやし業者として答えて` | 指定した役割に切り替え、次の切り替えまで維持します。 |
| `R01として答えて` | 役割IDで切り替えます。 |
| `全員の意見を聞きたい` | 全員がそれぞれ答えるモードに戻ります。 |
| `立場の違いを整理して` | 一時的に整理者として関心と意見の違いを示します。学習上の正解は示しません。 |
| `今の役割を教えて` | 現在の回答モードを確認します。 |

一つのAIが複数の役割を演じます。それぞれが独立したAIや記憶を持つ仕組みではありません。管理案内と人物としての回答は区別します。

## 設定を変更するとき

作成用スキルに、最新の「設定資料」と変更内容を渡します。新しい会話では保存した設定資料を添えてください。

~~~text
添付した設定資料のR01について、「目的・優先順位」を変更してください。
安定した取引の継続を最優先にしてください。
関係のない設定は維持し、設定資料とGem用プロンプトの完成版を出力してください。
~~~

任意設定だけの変更では、変更のない必須項目は聞き直しません。必須設定やその前提に変更がある場合は、影響を受ける項目を再確認してから完成版を出力します。役割の追加には既存の確認済み設定と必要設定を適用します。

更新された設定資料を保存し、新しいプロンプト全体でGemの指示を置き換えて保存します。役割カードの編集は、保存済みのGemに自動で反映されません。役割ごとに独立したプロンプトを求めた場合は、それぞれに必要設定・必須設定・実行規則がすべて含まれます。

作成・編集・役割との対話は日本語で行い、API・プラグイン・追加スクリプトは使いません。Geminiアカウントへの設定と、実際の対話動作の確認は未実施です。
